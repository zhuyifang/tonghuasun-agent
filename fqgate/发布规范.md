# FQGate 发布与更新规范

本规范用于发布 FQGate 安装包，并为程序中的“更新”页面提供版本说明和下载信息。FQGate 与 Agent 插件分别管理版本，不共用版本号。

## 固定地址

程序优先从本项目的 Gitee 镜像读取以下文件，失败时读取 GitHub 主仓库 `main` 分支中的同一路径：

- 当前稳定版本：`fqgate/releases/stable.json`
- 指定版本内容：`fqgate/releases/<版本号>.json`

GitHub 和 Gitee Release 标签都固定为 `fqgate-v<版本号>`。安装包地址由仓库地址、标签和文件名拼装，清单不能填写其他下载站地址。程序优先使用 Gitee，Gitee 不可用时自动改用 GitHub。

例如，Windows 0.2.0 安装包固定为：

- Gitee：`https://gitee.com/qicuo/tonghuasun-agent/releases/download/fqgate-v0.2.0/FQGate-0.2.0-windows-x64.exe`
- GitHub：`https://github.com/zhuyifang/tonghuasun-agent/releases/download/fqgate-v0.2.0/FQGate-0.2.0-windows-x64.exe`

## 清单格式

每个版本保存一份完整清单，`stable.json` 必须与当前稳定版本的清单内容一致。

```json
{
  "schemaVersion": 1,
  "component": "fqgate",
  "channel": "stable",
  "status": "published",
  "version": "0.2.0",
  "publishedAt": "2026-09-10",
  "minimumSupportedVersion": "0.1.0",
  "releaseNotes": [
    "第一条面向用户的更新内容。",
    "第二条面向用户的更新内容。"
  ],
  "packages": [
    {
      "platform": "windows",
      "architecture": "x86_64",
      "installMode": "replaceExecutable",
      "fileName": "FQGate-0.2.0-windows-x64.exe",
      "size": 12345678,
      "sha256": "填写安装包的小写 SHA-256"
    },
    {
      "platform": "macos",
      "architecture": "aarch64",
      "installMode": "openPackage",
      "fileName": "FQGate-0.2.0-macos-arm64.zip",
      "size": 12345678,
      "sha256": "填写安装包的小写 SHA-256"
    }
  ]
}
```

字段要求：

- `status` 只能是 `unpublished` 或 `published`。准备期间使用 `unpublished`，此时允许暂不填写安装包。
- `version` 和 `minimumSupportedVersion` 使用三段式版本号。最低支持版本不能高于本次发布版本。
- `releaseNotes` 写 1 至 6 条，每条不超过 80 个字，只写用户能够感知的变化。
- `size` 是安装包的实际字节数，`sha256` 使用 64 位小写十六进制值。
- Windows x64 使用 `replaceExecutable` 和单文件 EXE；macOS 使用 `openPackage` 和 ZIP 或 DMG。
- 正式清单不得登记测试包、调试文件、符号文件或本机路径。

## 发布顺序

1. 更新 FQGate 的版本号和本版本更新内容，完成全量测试。
   同步更新私有源码中的 `assets/release/current.json`，作为断网时随程序提供的同版本副本。
2. 分别构建并在对应系统上验证安装包。
3. 在 GitHub 和 Gitee 创建同名的 `fqgate-v<版本号>` Release，上传文件名及内容完全相同的安装包。Gitee 暂时不可用时至少先完成 GitHub。
4. 用安装包实际大小和 SHA-256 完成 `<版本号>.json`，将状态改为 `published`。
5. 先提交并确认版本清单可访问，再用同样内容更新 `stable.json`。
6. 使用旧版本检查一次自动下载和“完成更新”，确认成功后再发布公告。

最后更新 `stable.json` 可以避免用户先看到新版本、但安装包或校验信息尚未就绪。

## 程序行为

- 程序启动后检查一次更新，此后每 8 小时检查一次。
- “更新”页面从指定版本清单显示当前版本的更新内容。
- 版本清单和更新内容优先从 Gitee 获取，失败时改用 GitHub 主仓库。
- 发现新版本后优先从 Gitee 后台下载，失败时改用 GitHub；文件大小和 SHA-256 均一致才会显示“完成更新”。
- 下载完成后不弹出升级对话框；用户进入“更新”页面手动完成更新。
- Windows 会替换当前单文件程序并重新启动；macOS 会打开已下载的安装包，由用户按系统提示完成安装。
